Rebuilding customer support from a dead-end form

Users had one option: “report a problem”. No answers, no screenshots, and when an agent typed a resolution, the ticket closed without the user ever getting a reply. I redesigned the whole loop.

The Problem

Support was a one-way street. The help page was a form, so every question, however simple, became a ticket. Users couldn’t attach a screenshot, so they had to describe charts, errors and portfolio mismatches in words. And the moment an agent typed a resolution, the ticket closed automatically. The user never saw an answer and had no way to say “that didn’t fix it”.

On the team’s side, the admin view was a flat list with a single “Resolve” button. There was no sense of which tickets were waiting on us and which were waiting on the customer.

What I Designed

Help before a ticket

A help centre organised around how people use the product: search and chat, AI scores and investor personas, portfolio, stacks and AI baskets, news and watchlist, and the indicator dashboard. Each topic answers the common questions step by step, with short video guides in English and Hindi, so users who prefer Hindi get the same help.

Better tickets when help isn’t enough

“Still need help?” sits at the end of every topic, with a call option or a support request. The request is tagged with the topic the user came from, and it accepts a screenshot, so the team sees the problem instead of reading about it.

Conversations, not closures

Every ticket is now a two-way thread in “My Tickets”. Users see the team’s reply, can respond, and a reply to a resolved ticket reopens it. Resolving is no longer the end of the conversation by default.

An admin console built for the queue

The team gets New, Active and Resolved views, an “Awaiting customer” status, message counts, the platform each ticket came from, search, filters, and CSV import and export.

AI ticket analysis

An AI agent reads a snapshot of the ticket queue and surfaces patterns for the team. It runs with read-only access: it can’t edit tickets, run commands or browse the web.

Answer what the product can answer, then make every remaining ticket a real conversation.

How I’ll Judge It

  • Deflection: how many help-centre visits end without a ticket.
  • Tickets per active user, to separate support load from growth.
  • Reopen rate, to see whether resolutions actually resolve.
  • Time to first reply, now that “awaiting customer” and “awaiting us” are visible.

What I Took Away

Support is part of the product, not a cost centre bolted onto it. The cheapest ticket is the one a good answer prevents, and the worst one is the ticket that closes while the user is still stuck.
